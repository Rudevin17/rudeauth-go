# RudeAuth Go SDK

Go client for a RudeAuth licensing server. Cross-platform (Windows, Linux, macOS),
with only `golang.org/x/crypto` and `golang.org/x/sys` as dependencies.

The client embeds only an application id and an Ed25519 **public** key. Every
response is signed and verified against that key before any field is trusted, so
a patched binary cannot be talked into a forged "success".

## Set it up with AI

Paste this into Claude Code, Cursor, or any LLM.

```
Add RudeAuth licensing to my Go app.
Read https://docs.rudeauth.com/llms.txt for how RudeAuth works, and follow this
SDK's AGENTS.md rules: no bool is_licensed(), embed the public key, verify before
trust, no offline cache, and gate real logic into a server-delivered payload.
My app id is <APP_ID> and my public key is <PUBLIC_KEY>.
```

## Install

```
go get github.com/Rudevin17/rudeauth-go
```

Requires Go 1.21 or newer.

## Quick start

```go
import "github.com/Rudevin17/rudeauth-go"

// appID and publicKey come from `rudeauth-cli app create`. Both are safe to
// embed: the public key verifies responses, it cannot forge them.
client, err := rudeauth.NewClient(appID, publicKey, "https://api.yourproduct.com")
if err != nil {
    return err
}

sess, err := client.Authenticate(userEnteredKey)
if err != nil {
    // errors.Is(err, rudeauth.ErrLicenseExpired), rudeauth.ErrDeviceLimit, ...
    return err
}
defer sess.Close()

offset, err := sess.Variable("offset") // server-side, rotatable
core, err := sess.File("core.dll")     // never shipped in your binary
```

## No "is licensed" boolean, by design

There is deliberately no function that returns a bool meaning "is this user
licensed". A boolean is one byte in memory and one branch in the disassembly.
`Authenticate` returns a `*Session` or an error, and the gating calls exist only
on a `*Session`, which cannot be constructed without a response signature that
verified against the key you compiled in. A rejected licence is a specific error,
not `false`.

## Errors

Match with `errors.Is`:

| Error | Meaning |
|---|---|
| `ErrNetwork` | server unreachable |
| `ErrSignatureInvalid` | the responder is not holding your application's key |
| `ErrNonceMismatch` | a replayed response |
| `ErrClockSkew` | this machine's clock is too far off |
| `ErrLicenseInvalid` | unknown, revoked or banned, deliberately indistinguishable |
| `ErrLicenseExpired` | user-actionable |
| `ErrDeviceLimit` | licence is bound to its maximum machines |
| `ErrDeviceBlacklisted` | this hardware is banned |
| `ErrSessionExpired` | re-authenticate |
| `ErrRateLimited` | back off |
| `ErrFileNotFound` | no such gated file for this application |

## Behaviour worth knowing

- **No offline mode, no cache.** If the server is unreachable, calls fail. A
  cached "last known good" state is exactly what an attacker induces by blocking
  the network.
- **A missed heartbeat is not a logout.** The session retries until its TTL
  genuinely lapses, so a brief network blip does not drop a paying customer.
  `Close` stops the heartbeat and zeroes the session key.
- **Fewer than two readable hardware components and the SDK refuses to
  authenticate**, rather than sending a weak identity the server would have to
  accept.
- **Fingerprints are forgeable.** Device binding deters casual licence sharing.
  It is not a control against a motivated attacker, and should not be described as one.

## How to use this wrongly

1. Fetching a payload and not using it. If your program runs fine without
   `core.dll`, an attacker deletes the call and ships.
2. Hardcoding a variable "just for testing". It ships. Rotate anything you rely on.
3. Wrapping the SDK in your own `isLicensed() bool`. That reintroduces the exact
   patch target this API was shaped to remove. Pass the `*Session` to the code
   that needs it.

## Platforms

Hardware fingerprinting is implemented per OS and follows a shared component set,
so a device is recognised identically across RudeAuth SDKs:

- Windows: machine GUID, volume serial, CPU, BIOS serial, board.
- Linux: machine-id, DMI product/board/serial, CPU model.
- macOS: IOPlatformUUID, hardware serial, model.

## Tests

The crypto is checked against known-answer vectors generated by the server's own
code (`testdata/vectors.json`), so a mismatch with the server fails a test rather
than shipping silently. The protocol flow is tested against an in-process server
that signs and seals exactly as the real one does.

```
go test ./...
```
